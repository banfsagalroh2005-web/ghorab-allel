# 🐦‍⬛ غراب الليل — نظام إدارة الموظفين

نظام ويب حقيقي مبني بـ **بايثون (Flask + SQLAlchemy)** مع واجهة عربية تعمل على الكمبيوتر والهاتف.

- حسابات حقيقية: **مدير (Admin)** و**موظف (Employee)** مع تسجيل دخول مشفّر (JWT + كلمات مرور مشفّرة)
- قاعدة بيانات **محلية** (SQLite) + قاعدة بيانات **على الإنترنت** (PostgreSQL) مع **مزامنة تلقائية ثنائية الاتجاه**
- واجهة متجاوبة للهاتف + قابلة للتثبيت كتطبيق (PWA)

---

## 1) التشغيل السريع

يلزم تثبيت Python 3.10 أو أحدث.

**ويندوز:** انقر مرتين على `start.bat`
**لينكس / ماك:** `./start.sh`

أو يدوياً:

```bash
python -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

افتح: **http://localhost:8000**

عند أول تشغيل تظهر في الشاشة بيانات **المدير الأول** (اسم المستخدم `admin` وكلمة مرور عشوائية). سيُطلب منك تغييرها عند أول دخول.
لتحديد كلمة المرور بنفسك: انسخ `.env.example` إلى `.env` وضع `ADMIN_PASSWORD=...` قبل التشغيل.

## 2) الحسابات والصلاحيات

| | المدير | الموظف |
|---|:---:|:---:|
| إدارة الموظفين والأقسام | ✅ | ❌ |
| رؤية كل الحضور / الرواتب / الإجازات | ✅ | ❌ (بياناته فقط) |
| تسجيل حضور وانصراف | يدوي لأي موظف | لنفسه فقط (بتوقيت الخادم) |
| طلب إجازة | ✅ | ✅ (ويستطيع إلغاء الطلب المعلّق) |
| قبول / رفض الإجازات | ✅ | ❌ |
| إنشاء الحسابات وإعادة كلمات المرور | ✅ | ❌ |
| الإعدادات والمزامنة | ✅ | ❌ |
| تغيير كلمة مروره | ✅ | ✅ |

**كيف تنشئ حساب موظف؟** من صفحة *الموظفون* ← *إضافة موظف* (املأ اسم المستخدم وكلمة مرور مؤقتة)، أو من *الحسابات* ← *إنشاء حساب*.
الحسابات الجديدة وكلمات المرور المُعاد تعيينها تُجبر صاحبها على تغييرها عند أول دخول.

الصلاحيات تُفرض **في الخادم** وليس في الواجهة فقط؛ فحتى لو حاول الموظف استدعاء الـ API مباشرة يُرفض (403).

**نسيت كلمة مرور المدير؟**

```bash
python manage.py reset-password admin كلمة_جديدة_قوية
```

## 3) قاعدة البيانات المحلية + قاعدة الإنترنت

التطبيق يدعم قاعدتين معاً ويزامن بينهما:

```
   ┌──────────────┐   مزامنة كل 30 ثانية (وبعد كل تعديل بثوانٍ)   ┌────────────────────┐
   │ SQLite محلية │ ◀────────────────────────────────────────────▶ │ PostgreSQL (النت)  │
   └──────────────┘                                                └────────────────────┘
```

**أ) إنشاء قاعدة مجانية على الإنترنت** (اختر واحدة): [Supabase](https://supabase.com) أو [Neon](https://neon.tech) أو [Render PostgreSQL](https://render.com).
انسخ رابط الاتصال (Connection string) من إعدادات مشروع Supabase، ثم ضع الرابط في ملف `.env` المحلي (انسخ `.env.example` وسمِّ النسخة `.env`):

```
REMOTE_DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require
```

 > مع Supabase استخدم رابط **Session pooler** إذا تعذّر الاتصال المباشر من شبكتك. لا ترسل رابط الاتصال أو كلمة المرور لأي شخص، ولا تضعهما في صور أو محادثات.

**قبل أول مزامنة:** احتفظ بنسخة إضافية من `data/local.db`. إذا احتاجت قاعدة SQLite القديمة إلى أعمدة المزامنة `updated_at` و`deleted`، ينشئ التطبيق نسخة احتياطية تلقائية بجانب ملف القاعدة قبل إضافة هذه الأعمدة. اجعل `DB_PRIMARY=local` في البداية إذا كانت بيانات الموظفين الحالية على جهازك هي النسخة المعتمدة؛ فهذا يجعل البيانات المحلية هي المرجع عند أول مزامنة.

أعد تشغيل التطبيق. الجداول تُنشأ تلقائياً. من **الإعدادات ← قواعد البيانات والمزامنة** ترى الحالة وزر **مزامنة الآن**.

**ب) وضعا العمل (`DB_PRIMARY`)**

| الوضع | متى تستخدمه |
|---|---|
| `local` (الافتراضي) | على جهازك/خادمك. سريع، **ويستمر بالعمل لو انقطع الإنترنت** ويزامن عند عودته. |
| `remote` | على استضافة سحابية قرصها مؤقت (Render/Railway…). قاعدة الإنترنت هي الأساس وتُنسخ محلياً. |

**ج) قواعد المزامنة (مهم أن تعرفها)**
- المزامنة ثنائية الاتجاه: أي سجل أحدث في أحد الطرفين ينتقل للآخر (**آخر تعديل يفوز**).
- الحذف «ناعم»، فيُزامَن أيضاً.
- إذا مُسحت القاعدة المحلية أو نُقل التطبيق لجهاز جديد، تُستعاد كل البيانات من الإنترنت تلقائياً عند أول تشغيل.
- المقارنة تعتمد على ساعة الجهاز، فاحرص أن تكون ساعات الأجهزة المتصلة بنفس القاعدة مضبوطة.

## 4) الهاتف

الواجهة متجاوبة بالكامل (قائمة جانبية منزلقة، نوافذ من الأسفل، أزرار كبيرة لتسجيل الحضور).

**على نفس شبكة الواي فاي:** شغّل التطبيق على الكمبيوتر، ثم افتح من الهاتف `http://عنوان-IP-الكمبيوتر:8000`
(اعرف العنوان بـ `ipconfig` على ويندوز أو `ip a` على لينكس. قد تحتاج السماح للمنفذ 8000 في جدار الحماية.)

**للاستخدام من أي مكان + تثبيته كتطبيق:** انشره على استضافة تدعم **HTTPS** (أسهل طريقة: Render أو Railway)، ثم من متصفح الهاتف اختر
*«إضافة إلى الشاشة الرئيسية / تثبيت التطبيق»*. (التثبيت كتطبيق يتطلب HTTPS ما عدا `localhost`.)

## 5) النشر على الإنترنت (مثال Render)

1. ارفع المشروع إلى GitHub (ملف `.gitignore` يمنع رفع `.env` والبيانات).
2. في Render: **New → Web Service** واربطه بالمستودع.
3. Build Command: `pip install -r requirements.txt` — Start Command: `python app.py`
4. أضف متغيرات البيئة: `REMOTE_DATABASE_URL`, `DB_PRIMARY=remote`, `ADMIN_PASSWORD`, `SECRET_KEY` (نص عشوائي طويل), `TIMEZONE`.
5. بعد النشر ستحصل على رابط `https://...` تفتحه من أي جهاز.

---

## 6) أمان — يرجى القراءة

- غيّر كلمة مرور المدير الافتراضية فوراً، واستخدم كلمات مرور قوية.
- عند النشر على الإنترنت استخدم **HTTPS** دائماً، وضع `SECRET_KEY` ثابتاً.
- كلمات المرور تُخزَّن مشفّرة (PBKDF2-SHA256) ولا يمكن استرجاعها.
- هناك حد لمحاولات الدخول الفاشلة (6 محاولات / 5 دقائق).
- خذ نسخاً احتياطية: ملف `data/local.db` + نسخ قاعدة الإنترنت من لوحة مزوّدها.
- بيانات الموظفين (رواتب، هواتف) حساسة؛ تأكد من الالتزام بقوانين حماية البيانات في بلدك.

## 7) هيكل المشروع

```
app.py            الخادم وكل واجهات الـ API والصلاحيات
database.py       جداول قاعدة البيانات واتصال المحلية/الإنترنت
sync.py           المزامنة ثنائية الاتجاه
config.py         قراءة الإعدادات (.env)
manage.py         أدوات سطر الأوامر (كلمة المرور / مزامنة)
static/           الواجهة (index.html) + ملفات تطبيق الهاتف (PWA)
data/             القاعدة المحلية (تُنشأ تلقائياً)
```

## نشر آمن على Render بعد التأكد من وجود البيانات في Supabase

- لا ترفع ملف `.env` أو قاعدة `data/local.db` أو `data/secret.key` إلى GitHub.
- في Render أضف متغيرات البيئة من لوحة الخدمة:
  - `DB_PRIMARY=remote`
  - `REMOTE_DATABASE_URL` = رابط Session Pooler من Supabase مع `sslmode=require`
  - `SECRET_KEY` = قيمة عشوائية طويلة وثابتة
  - `ADMIN_USERNAME` = اسم المدير الحالي
  - `TIMEZONE=Asia/Damascus`
  - `TOKEN_HOURS=12`
  - `SYNC_INTERVAL=30`
  - `SEED_DEMO=0`
- لا تضع كلمة المرور داخل ملفات المشروع أو في GitHub.
- قبل النشر، تأكد من وجود بيانات الموظفين والحسابات المطلوبة في جداول Supabase. هذه الحزمة لا تتضمن قاعدة SQLite المحلية أو أسرار الاتصال.
